# Haregi 画面モック(claude)

`docs/`(specification.md / architecture.md / persona.md)の **Must 機能**を基準に作成した静的 HTML モック。
`index.html` をブラウザで開くと全画面の索引が出る(ビルド不要・依存なし)。

```
open mock/claude/index.html
```

## 収録画面

| ファイル | パス | 内容 |
| --- | --- | --- |
| `index.html` | — | モック索引 |
| `landing.html` | `/` | ランディング(未ログイン) |
| `signup.html` | `/signup` | 会員登録(バリデーションエラー表示例つき) |
| `login.html` | `/login` | ログイン(保護ルートからのリダイレクト案内つき) |
| `forecast.html` | `/forecast` | メイン画面・通常状態(`status: 'fresh'`)+ 保存トースト |
| `forecast-stale.html` | `/forecast` | last-known-good(`status: 'stale'`)+ 未保存離脱の警告ダイアログ |
| `forecast-error.html` | `/forecast` | 予報取得失敗(502)+ 409 競合トースト |
| `forecast-drawer.html` | `/forecast` | モバイルのドロワーナビ展開状態(**768px 以下に狭めて確認**) |
| `history.html` | `/history` | 履歴 最小版(直近30件) |
| `history-empty.html` | `/history` | 履歴の空状態 |

共通スタイルは `styles.css`(トークン・ボタン・カード・フォーム・ダイアログ・ドロワー・トースト)、画面固有は `screens.css`。
`theme.js` はライト / ダークの切替のみを担う(下記)。

## ライト / ダークの切替

ヘッダー右上のボタンで切り替えられる。

- 既定は **OS の設定に追随**(`html` に `data-theme` を付けず、`:root { color-scheme: light dark }` に任せる)
- ボタンを押すと `html[data-theme='light' | 'dark']` を明示し、`localStorage` に保存する。**ページを跨いでも保持される**
- `file://` で開くと `localStorage` が使えないブラウザがあり、その場合はそのページ内だけの切替になる(エラーにはならない)
- **色トークンは `:root` に1回だけ定義**する。ライト / ダークの値は `light-dark()` に並べて書いてあり、
  `data-theme` の明示指定は `color-scheme` を固定するだけでよい(トークンの再定義が不要)。
  実装では Tailwind v4 の `@custom-variant dark` + 同じ `data-theme` 方式に置き換えられる想定

> `light-dark()` は Baseline **Newly available**(2024-05 / Chrome 123・Safari 17.5・Firefox 120)。
> フォールバックを入れると定義ブロックが再び分裂して1本化の意味が失われるため、
> **開発者向けモックという前提で意図的に入れていない**。プロダクト側の対応方針は別途決める。

## モックで表現した仕様

- **1画面で1週間分を一括入力**(persona.md §3 / spec §3)。デスクトップは1日1行のテーブル、モバイル幅(900px 以下)では1日1カードに切り替わる
- **地域切替セレクタ**と、切替中に保存した記録が履歴で地域名つきに見えること(決定事項 #29 / #30)
- **予報の鮮度と出どころ**: 発表時刻・「地域の代表地点(東京)の予報」表記・`fresh` / `stale` のバッジ(spec §5)
- **「出典: 気象庁ホームページ」を全ページのフッターで常時表示**(法的要件)
- **予報取得失敗(502)でも入力・保存が継続できる**こと。気温欄は「気温なし」表示(`snapshotStatus: 'unavailable'`)
- **週間予報の欠損(空文字 `""`)** を `—` として壊さず表示(8月14日の最低気温)
- **未保存の変更**を保存バーで明示し、離脱時にダイアログで警告する(spec §5)
- **409(同時編集の競合)**を再読み込み導線つきのトーストで通知(決定事項 #32)
- **モバイルのドロワーナビ**(spec §2.4 Must。shadcn/ui の Sheet を想定)
- **履歴の最小版**: 日付・3項目・保存気温・地域名のみ。写真・集計・フィルタは持たない(spec §2.3)
- 入力制約の表示: コーデ各項目は50文字、3項目すべて空にすると記録が削除される(spec §4)

## 視覚設計

情報設計はそのままに、視覚レイヤーだけを一度作り直している(骨格・HTML 構造は不変)。

- **色は OKLCH**。ブランド軸はアプリ名の由来「晴れ」に沿った**空のインディゴ**(`oklch(52% 0.16 258)`)で、
  主要ボタン・フォーカスリング・現在地・「今日」・出典表記に使う
- **気温はブランドと色相を離す**(暖 42° / 寒 215° / ブランド 258°)。ペルソナの中心課題が「気温の読み違い」であるため、
  気温は他のテキストより大きく重く出し、**最高気温を主・最低気温を従**として階層をつけている
- **Web フォント依存は持たない**(ビルド不要・オフラインで開ける、を維持)。見出しは `Hiragino Sans` を先頭に置いた
  display スタック + ウェイト・スケール・字間で階層を作る
- **ボタンは8状態**(default / hover / focus-visible / active / disabled / loading / error / success)。
  静的なモックでも `.is-hover` / `.is-focus` / `.is-active` を付ければ各状態を並べて確認できる
- モーションは `--dur-*` / `--ease-*` トークン経由。`prefers-reduced-motion: reduce` では
  空間移動を 140ms のクロスフェードに畳み、**情報を持つ動き(スピナー)は止めずに遅くする**

## 前提・制限

- **静的 HTML/CSS が主体で、JavaScript はテーマ切替(`theme.js`)のみ。フォームやその他のボタンは動作しない**(見た目と情報設計の確認用)。
  ドロワー・ダイアログ・トーストは「開いた状態」を別ファイル/固定表示で再現している
- 実装は TanStack Start + Tailwind CSS v4 + shadcn/ui で行う。この CSS はそのトークン設計を素の CSS で近似したもので、
  **そのまま移植する前提ではない**
- 表示している気温・天気・コーデ内容はすべてダミー(2026年8月8日〜14日・東京都を想定)
- 地域セレクタの選択肢は抜粋。実装では `master-data/areas.ts` の全58区分を出す
- ダークモード(Could)は全画面で確認できる。写真アップロード(Should)は未収録
